**4 литерала (3 уникальных значения) остаются как есть — решение
владельца, не моё:**

| Литерал | Где | Причина |
|---|---|---|
| `oklch(0.70 0.22 18)` | цвет иконки в бейдже строки | ближайший по оттенку — `--ruby`, но разрыв по светлоте 0.22 — заметно больше любого одобренного в Task 085 сдвига |

**Находка для Task 087: семье `--warning` нужен второй уровень**
(например, `--warning`/`--warning-strong` или похожая пара) — не
находка этого пилота специально, а прямое следствие того, что здесь её
не стали подгонять молча.

### Обнаруженные при миграции ловушки (входные данные для Task 087)

Обе — не про эту задачу конкретно, но встретятся на каждом следующем
экране, если не знать о них заранее:

1. **`dark:`-варианты компонентов перебивают токен-классы.** `Button`
   `variant="outline"` содержит `dark:bg-input/30 dark:border-input
   dark:hover:bg-input/50`. Приложение всегда в тёмной теме
   (`<html class="dark">`), поэтому эти классы всегда активны.
   `tailwind-merge` не считает `bg-muted` (без модификатора) и
   `dark:bg-input/30` конфликтующими — оба остаются в выводе, и
   `dark:`-вариант выигрывает каскадом. Без явного `dark:bg-muted
   dark:border-primary/22 dark:hover:bg-muted` кнопка «Прочитать все»
   рендерилась с `bg-input` на 30% прозрачности вместо непрозрачного
   `--muted` — проверено через `getComputedStyle`, не разница, а
   реальная ошибка. Пойман и исправлен здесь; при 087 писать `dark:`-пару
   для каждого утилити-класса, которым перебивается `dark:`-вариант
   компонента.
2. **`Empty` не даёт border-width.** Базовый класс — `border-dashed`
   (только стиль), без `border` (ширина). Без явного `border` в
   `className` бордер невидим (`border-width: 0px`, подтверждено
   computed style). Тоже пойман и исправлен здесь.

### Главный вопрос — компонент `AuthField`, не «подошёл/не подошёл»

В отличие от пилота (где каждый элемент либо становился компонентом
`components/ui`, либо оставался своим), здесь у `AuthField` — подчёркивание
(прозрачный фон, только `border-bottom`), а у `Input` из `components/ui` —
коробка (рамка со всех сторон, `rounded-md`, `bg-input/30`, `ring` на
фокусе). Разные визуальные языки. Проверено: паттерн подчёркивания
(`borderBottom` на фокусируемом `<input>`) в кодовой базе за пределами
`features/auth` не встречается — все остальные `borderBottom`-литералы
это разделители секций, не поля ввода. Значит третий вариант (CVA-вариант
`Input` под подчёркивание) не оправдан — один экран не повод менять общий
компонент. Решение владельца: `AuthField` остаётся своим компонентом,
цвета переведены на токены, `Input` не тронут.

### Императивный фокус/блюр → CSS — исправлено, не только мигрировано

`auth-field.tsx` и `birthdate-field.tsx` двигали цвет рамки через
`e.currentTarget.style.borderBottomColor` в `onFocus`/`onBlur` — мимо
CSS-каскада и `:focus`. Заменено на `focus:border-b-primary/70` и
`aria-invalid:border-b-destructive/80` + `aria-invalid:focus:border-b-destructive`
(добавлен `aria-invalid={!!error}`, которого не было вообще — заодно
чинит объявление ошибки скринридером). `focus:`, не `focus-visible:` —
на текстовом поле индикация фокуса нужна одинаково для клика и для
Tab. В `birthdate-field.tsx` `useState(focused)` и оба обработчика
существовали только ради этого цвета — после перехода на CSS состояние
стало мёртвым и удалено вместе с обработчиками, а не оставлено рядом.

### Находка: уровень наведения внутри тон-семьи требует своего токена

Тот же класс проблемы, что `--warning` в пилоте, но в семье `--primary`
(тон 12). `oklch(0.78 0.22 12)` — высветленное состояние primary-ссылки
при наведении — использовалось через `onMouseEnter`/`onMouseLeave` **шесть
раз в трёх файлах** (`sign-up-form.tsx` ×3, `sign-in-form.tsx` ×1,
`profile/page.tsx` ×2), а не как единичное значение в блоке авторизации,
как показалось на первый взгляд. Первое предложение — эмулировать тем же
`hover:brightness-110`, что уже используется на кнопках, — не подтвердилось
при проверке: `brightness-125` (ближе к нужному скачку светлоты) в проекте
не встречается вообще, `brightness-110` — не тот масштаб и не тот
элемент (кнопки, не текстовые ссылки). Заведён токен `--primary-hover:
oklch(0.78 0.22 12)` (точное значение, попиксельно совпадает с прежним
видом) в `globals.css`, использован в четырёх местах блока авторизации;
два вхождения в `profile/page.tsx` не тронуты — тот экран мигрирует
отдельно и токен подхватится сам. **Правило на будущее**: при миграции
проверять не только «валиден ли токен для этого значения», но и
«не повторяется ли то же значение в других уже нетронутых файлах» —
единичное на вид значение может быть общим решением, просто без токена.

разным токенам разница выросла бы до 0.079 — вдвое больше порога
заметности, и один и тот же сценарий (ошибся при входе → восстановление
пароля) показал бы два разных оттенка одной и той же роли. Оба сведены к
`--foreground`. **Правило на будущее**: если два литерала одной роли уже
неразличимы на глаз, они едут на один токен, даже когда «ближайший сосед»
у них разный по чистому числу — сначала смотреть на отношения между
элементами, потом на расстояние до токена. На `profile`/`discover`
(сотни литералов каждый) таких пар будет много.

### Остаются литералами — та же причина, что `--warning`

5 из 122: `oklch(0.62 0.18 25)` (×3 — текст ошибки поля, `AuthField`,
`BirthdateField`, чекбокс) и `oklch(0.70 0.16 25)` (×2 — текст баннера
общей ошибки, `sign-in`/`sign-up`). Та же тон-семья 25, что и
`--destructive` (0.52), три реальных уровня на один токен — не подгонялись
молча, причина документирована прямо в коде рядом с каждым.

### Проверка

Полный ручной сценарий (не только внешний вид): регистрация нового
аккаунта → редирект в `/onboarding` с данными формы → выход → вход тем
же аккаунтом — пройден целиком на реальном backend. Клавиатура: Tab по
всей форме `/join`, фокус виден на каждом поле (подтверждено и
скриншотом, и `getComputedStyle` — на `birthdate` рамка визуально
темнее из-за alpha-смешения с фоном, но `border-bottom-color` совпадает
с `--primary/70` компьютерно). Ошибка + фокус одновременно даёт более
насыщенный `--destructive` без alpha — тоже проверено через
`getComputedStyle`, не только на глаз. `/signin` и `/join` при 1280 —
попиксельно идентичны состоянию до миграции (сравнение через `git
stash`, не по памяти). 1920 — геометрия декоративных пятен Task 091

`getBoundingClientRect()` с записанными в Task 091 значениями. Консоль
на каждом экране — полная перезагрузка, не переход по ссылке (см.
CLAUDE.md); новых ошибок/issues нет, кроме уже известного 401 на
`/auth/refresh` при выходе из системы (не относится к этой задаче).
