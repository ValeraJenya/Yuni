## Метод

Node-скрипт со сбалансированным парсингом скобок (наивный `[^)]*}` ломается
на вложенных скобках в динамических выражениях — см. находку выше). Обходит
`apps/frontend/**/*.{ts,tsx}`, кроме `node_modules`/`.next`, ищет `oklch(`,
парсит до соответствующей закрывающей скобки посимвольным подсчётом
глубины, записывает `{file, line, value}` для каждого вхождения.

```js
function walk(dir, files) { /* обходит .ts/.tsx, пропускает node_modules/.next */ }
for (const fp of files) {
  const lines = fs.readFileSync(fp, 'utf8').split('\n');
  for (let ln = 0; ln < lines.length; ln++) {
    let idx = 0;
    while (true) {
      const pos = line.indexOf('oklch(', idx);
      if (pos === -1) break;
      let depth = 0, start = pos + 5, end = -1;
      for (let i = start; i < line.length; i++) {
        if (line[i] === '(') depth++;
        else if (line[i] === ')') { depth--; if (depth === 0) { end = i; break; } }
      }
      const val = line.slice(pos, end + 1);
      if (val.includes('${')) dynamic.push([fp, ln + 1, val]); // не статическое значение
      else uniq.get(val, []).push([fp, ln + 1]);
      idx = end + 1;
    }
  }
}
```

Токены `globals.css`: регэксп `--([a-z0-9-]+):\s*([^;]+);` внутри блока
`:root { ... }`, из значения вытаскиваются все `oklch(...)`. Для каждого
литерала: `exact`, если нормализованная строка (пробелы схлопнуты)
совпадает с полным значением какого-то токена (включая альфу, если она
там есть); иначе `alpha`, если базовая тройка `L C H` (без `/ альфа`)
совпадает с базовой тройкой какого-то токена; иначе `outside`.

Neutral/colored: `chroma ≤ 0.015` — нейтральный, иначе цветной, ровно как
в постановке (порог подтверждён — числа совпали).

Скрипты и промежуточные JSON лежат вне репозитория (scratchpad сессии),
воспроизводятся по коду выше и по методу ниже за пять минут на текущем
`main`.

## 2. Проект нейтральной шкалы

### Форма распределения — ключевая находка

67 различных значений `L` в диапазоне 0.03–0.98, соседние шаги отличаются
на 0.005–0.03 почти равномерно (проверено — таблица разрывов построена
для всех 66 соседних пар, ни один разрыв не превышает 0.03). Это значит:
**в нейтральном ряду нет естественных больших пустот**, по которым можно
было бы разрезать шкалу «руками» и сказать «вот кластер, а вот пустота».
Ряд ведёт себя как почти непрерывный циферблат, а не как дискретный набор
ступеней — то есть 43/67 ступеней тут не потому, что кто-то плодил
токены, а потому что литералы реально писались как «чуть темнее» /
«чуть светлее» без общей сетки.

Отсюда: любое схлопывание в N уровней — не «нашёл кластеры в данных», а
явное проектное решение о допустимой цене (сдвиге). Число ниже выведено
не из пустот, а из **точки убывающей отдачи** на графике «сколько мы
экономим кластеров против того, сколько это стоит в сдвиге» — метод ниже.

### Метод: оптимальное 1D-кластерование, взвешенное по частоте

Для набора точек `{L, вхождений}` через динамическое программирование
найдено оптимальное разбиение на `k` кластеров, минимизирующее
взвешенную сумму квадратов отклонения от среднего кластера (тот же
критерий, что у k-means, но точное решение для одномерного случая, а не
приближение). Посчитано отдельно для «поверхностей» (`L < 0.5`, 37
ступеней / 343 вхождения) и «текста» (`L ≥ 0.5`, 30 ступеней / 130
вхождений) — раздел не по пустоте в данных (её и тут нет), а по
семантике тёмной темы: тёмные значения почти всегда фон/карточка/бордер,
светлые — текст. Разброс массы (343 vs 130) это подтверждает.

Суммарная стоимость (взвешенная сумма квадратов отклонений) по `k`:

**Поверхности (37 ступеней):**

| k | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|---|---|---|---|
| cost | 1.334 | 0.566 | 0.318 | 0.214 | 0.126 | 0.091 | 0.073 | 0.058 | 0.045 |
| cost[k]/cost[k-1] | — | 0.42 | 0.56 | 0.67 | **0.59** | 0.72 | 0.80 | 0.79 | 0.78 |

**Текст (30 ступеней):**

| k | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|
| cost | 0.692 | 0.260 | 0.147 | 0.103 | 0.062 | 0.046 | 0.031 |
| cost[k]/cost[k-1] | — | 0.38 | 0.57 | 0.70 | **0.60** | 0.74 | 0.67 |

В обеих таблицах отношение падает локально при переходе к `k=6`
(0.59 и 0.60 — лучше соседних `k=5→6` окрестностей), после чего каждый
следующий кластер даёт всё меньше пользы (отношение растёт к 0.7–0.8).
Формальный элбоу — `k=6` для обоих рядов. Это больше, чем прикидка
«четыре-пять» для текста — называю прямо и предлагаю оба варианта.

**Предлагаю: 6 уровней поверхностей + 5 уровней текста = 11 токенов.**
Для текста беру не элбоу-`k=6`, а `k=5`: разница в abs. cost между 5 и 6
для текста небольшая (0.103→0.062, но это уже 130 вхождений на 5-6
кластеров — сдвиг на глаз почти не отличается, см. таблицу ниже), а
`k=5` укладывается в изначальную прикидку и даёт на один токен меньше.
Если предпочитаете формальный элбоу — `k=6` для текста показан отдельно.

## 4. Прозрачности

50 значений / 172 вхождения в корзине `alpha` — но распределение внутри
неё крайне неравномерное:

| Базовый токен | Разных альф | Вхождений |
|---|---|---|
| `--primary`/`--rose` (`0.65 0.26 12`) | **30** | **137** (80% корзины) |
| `--border`/`--sidebar-border` (`0.20 0.010 15`) | 4 | 8 |
| `--destructive` (`0.52 0.20 25`) | 3 | 8 |
| `--ruby` (`0.48 0.22 18`) | 3 | 3 |
| `--background`/`--obsidian` (`0.09 0.008 15`) | 3 | 3 |
| `--input`/`--sidebar-accent` (`0.16 0.010 15`) | 2 | 6 |
| `--*-foreground` (`0.98 0 0`) | 2 | 4 |
| `--card`, `--sidebar`, `--foreground`-семейство | по 1 | по 1 |

Один только `--primary` встречается на **30 разных уровнях
прозрачности** — от 0.04 до 0.80, без явной группировки вокруг
небольшого набора «круглых» значений (полный список: 0.04, 0.05, 0.06,
0.07, 0.08, 0.10, 0.12, 0.14, 0.15, 0.16, 0.18, 0.20, 0.22, 0.24, 0.25,
0.28, 0.30, 0.32, 0.35, 0.36, 0.38, 0.40, 0.45, 0.50, 0.55, 0.60, 0.65,
0.70, 0.75, 0.80). По всем цветовым и нейтральным литералам с альфой —
51 различная дробь, тоже без доминирования 2-3 значений.

**Вывод: дискретные токены под альфу не подходят** — 30 токенов ради
одного `--primary` не имя, а нумерация. Единый приём:

**`color-mix(in oklab, var(--token) N%, transparent)`** — уже применяется
ровно один раз в этой самой кодовой базе, в
[discover/page.tsx:115](../../apps/frontend/app/(app)/discover/page.tsx#L115):
`color-mix(in oklab, var(--primary) 10%, transparent)`. Это не
изобретение нового приёма, а обобщение уже принятого на весь проект.

Модификатор Tailwind (`bg-primary/20`) рассмотрен и отклонён для этого
конкретного случая: все 293 литерала живут в inline `style={{}}`, а не в
`className`. `--color-primary` и остальные уже зарегистрированы в
`@theme inline` (globals.css:91 и далее), то есть Tailwind-модификатор
технически работает — но только если код одновременно переедет с inline
`style` на `className`, а это уже не разметка токенов, а рефакторинг
разметки, вне periметра этой задачи («код экранов не трогаем»).
`color-mix` работает в `style={{}}` без этой миграции.

Отдельных токенов под конкретную альфу не предлагаю ни под одну
комбинацию — ни одна не встречается настолько часто и настолько
самостоятельно по смыслу, чтобы заслуживать имени отдельно от базового
цвета (`--rose-glow` уже существует и покрывает единственный
действительно частый случай — `0.65 0.26 12 / 0.28`, 6 вхождений,
`exact`-корзина, раздел 1).

## Итог: что предлагается на утверждение

- Нейтральная шкала: **6 уровней поверхностей + 5 уровней текста = 11
  токенов** (раздел 2), с показанными сдвигами по каждой ступени и
  альтернативами k=5/k=7 (поверхности) и k=6 (текст) для сравнения цены.
- Три новых цветных токена-состояния: **`--online`** (145),
  **`--superlike`** (220), **`--warning`** (28) — раздел 3.
- Уточнение: «18 → accent» в постановке неточно, по факту это
  `--ruby` — раздел 3.
- Приём для прозрачностей: **`color-mix(in oklab, var(--token) N%,
  transparent)`** для всех alpha-вариантов существующих и новых токенов,
  без отдельных alpha-токенов — раздел 4.
- Не трогать при миграции: `veil-overlay.tsx` (10 значений, декоративная

- `globals.css` не менялся. Токены добавляются отдельным коммитом после
