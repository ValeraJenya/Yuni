## Цель

Task 027 задаёт backend-контракт трёх этапов общения после матча: staged permissions, игровые вопросы, стартовые фразы, системные сообщения и ограничения по voice на этапе 2.

Task 028 и Task 029 зарезервированы для UI игр/анимаций и frontend этапов. Их scope и статус эта задача не меняет.

## Что реализовано

- Staged-endpoints:
  - `GET /chat/conversations/:id/stage`
  - `GET /chat/starters`
  - `GET /chat/conversations/:id/game/current`
  - `POST /chat/conversations/:id/game/postpone`
  - `POST /chat/conversations/:id/game/:gameId/answer`
- 3 стадии общения (`stage` 1/2/3) с разными permissions.
- Голосовые лимиты на этапе 2: максимум 60 секунд на сообщение, 90 секунд суммарно на человека.
- Игры (`ChatGame`, `GameAnswer`) появляются по порогам сообщений.
- `ConversationStarter` модель и `GET /chat/starters` endpoint.
- Системные сообщения при переходе стадий: `isSystemMessage: true`, `senderUserId: null`.

## Реализовано частично

- `voiceDurationSec` — просто число от клиента. Физической проверки длительности файла и обрезки аудио нет, вопреки формулировке спеки.

## Открытые проблемы

- Race condition при одновременных первых ответах в игре: участник читает игру вне транзакции, считает ответы отдельно — два одновременных ответа могут оба увидеть `count=1` и не выставить `completedAt`. Вынесено в Task 043.
- Лимит голосовых 90 секунд обходится параллельными запросами: остаток лимита считается от уже прочитанного вне транзакции объекта `conversation`. Вынесено в Task 044.
- Таблица `conversation_starters` создаётся миграцией, но нигде не наполняется данными — `GET /chat/starters` на чистой БД всегда возвращает пустой список. Вынесено в Task 045.

## Вынесено в отдельные задачи

## Продуктовая спецификация этапов

Этот раздел описывает целевой дизайн, а не полностью доказанное фактическое состояние реализации.

| Этап | Целевые возможности | Условие перехода |
|---|---|---|
| Stage 1 — начало знакомства | Text, стартовые фразы, две игры; voice и attachments недоступны | 2 завершённые игры |
| Stage 2 — среднее общение | Text + voice с лимитами; attachments недоступны; три игры | 3 завершённые игры |
| Stage 3 — открытое общение | Text + voice + attachments | Конечный этап |

Целевой production voice flow должен получать реальный audio-файл, самостоятельно определять длительность и физически обрезать данные до разрешённого остатка лимита. Текущий backend этого не делает.
