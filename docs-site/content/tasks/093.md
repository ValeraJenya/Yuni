## Статус

`review` · P2

## Scope-check

Задача доопределяет семантические уровни уже найденных цветовых семейств в
дизайн-системе. Кодовый scope ограничен `apps/frontend/app/globals.css`;
экраны, `features/**`, `components/**` и `components/ui/**` не менялись.
Существующие значения токенов не менялись. Документационный scope:
дополнение к датированному аудиту, эта страница и устойчивые записи ROADMAP.

## Основание

Инвентарь повторно проверен на `origin/main` `bbcb257` после миграций 086,
087a и 087b. Числа без контекста оказались недостаточны: близкие значения
иногда обозначают foreground и поверхность, а одинаковый hue — разные
семантические роли. Поэтому каждое значение разобрано по файлу, строке и
типу элемента до выбора уровней.

Текстовый замер совпал с постановкой, кроме уточнения hue 25:
`oklch(0.70 0.16 25)` найдено 3× текстовым поиском, но одно совпадение —
комментарий Task 087a; runtime-элементов два.

## Решение

В `globals.css` добавлены семь custom properties и семь соответствующих
`--color-*` записей в `@theme inline`:

| Токен | Значение | Основание |
|---|---|---|
| `--destructive-text` | `oklch(0.62 0.18 25)` | 3× inline error text; цель для схлопывания `0.60` (8×: 7 текстов и 1 pending-action иконка, `ΔL +0.02`) |
| `--destructive-strong` | `oklch(0.70 0.16 25)` | 2× runtime general-error banner text |
| `--online-foreground` | `oklch(0.80 0.18 145)` | 3× текст online-бейджей |
| `--success` | `oklch(0.62 0.15 145)` | 3× feedback об успешном действии; не online-presence |
| `--info-muted` | `oklch(0.65 0.20 220)` | 6× рамки и свечения superlike |
| `--info-hover` | `oklch(0.82 0.18 220)` | 1× hover-foreground superlike |
| `--ruby-foreground` | `oklch(0.70 0.22 18)` | 1× UI-иконка уведомления |

Существующие `--destructive`, `--online`, `--info`, `--warning` и `--ruby`
оставлены побайтово неизменными. `--success` намеренно не назван уровнем
online: обратная связь об успешном действии и присутствие человека в сети —
разные роли, случайно совпавшие по тону.

### Схлопывания

- hue 25: `0.60→0.62`, `ΔL +0.02`; структурный `0.55→--destructive=0.52`,
  `ΔL −0.03`; strong `0.70` остаётся отдельно;
- hue 220: `0.72 0.18→0.72 0.20` без сдвига L, `0.74→0.72`
  (`ΔL −0.02`), `0.75→0.72` (`ΔL −0.03`); `0.65` и `0.82` — отдельные
  structural/hover роли;
- hue 18: декоративные glows остаются на `--ruby=0.48`, UI-foreground
  `0.70` отдельный; одиночная дымка `0.65 / 0.022` не становится системным
  уровнем;
- hue 28: нового токена нет, все значения мигрируют на `--warning=0.70`.

### Осознанное изменение hue 28

Два текста `oklch(0.78 0.16 28)` находятся в
`apps/frontend/app/(app)/notifications/page.tsx:252` (action error) и
`:371` (unread badge). При будущей миграции на `--warning` они станут
темнее на `ΔL −0.08`, что выше порога заметности `0.05` из Task 085.
Это утверждённое визуальное изменение, не перенос один в один. Контраст
после схлопывания остаётся не ниже примерно `6.96:1`, поэтому WCAG 4.5:1
не пересекается.

## `--destructive` не изменён

`--destructive=oklch(0.52 0.20 25)` не встречается литералом на экранах,
но используется через classes/variants в `components/ui`: Button, Alert,
Badge, Toast, form/field/menu и aria-invalid states. Изменение затронуло бы
не только текст, но и заливки, рамки, rings и hover. Это отдельное решение
владельца с component-wide visual/contrast review, не часть Task 093.

## Контраст и Task 089

Task 093 не чинит найденные пары, а передаёт их в Task 089:

- `oklch(0.60 0.18 25 / 0.85)` на фонах L≈0.09–0.11 даёт
  `3.63–3.67:1`: `matches/page.tsx:300`, `messages/page.tsx:360,640,778`,
  `profile/page.tsx:645,1051`;
- danger-текст `oklch(0.60 0.18 25 / 0.75)` в `profile/page.tsx:285`
  даёт `3.03–3.05:1`;
- обе группы ниже 4.5:1 для обычного текста.

Расчёт использует браузерно скомпозированные sRGB-пиксели и WCAG relative
luminance. Alpha-композиция уже линеаризованных RGB-каналов дала бы
завышенные числа и не соответствует фактическому браузерному пикселю.

Отдельное правило для миграции: alpha текстового цвета нельзя переносить
механически. Прозрачность режет контраст, поэтому после выбора токена и
alpha-модификатора пересчитывается каждая реальная пара текста и фона, а не
только базовый литерал.
