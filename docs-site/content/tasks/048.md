## Проблема

- Frontend-тип `ChatMessage.senderUserId` в `chat-api.ts` объявлен обязательным `string`, хотя системные сообщения возвращают `null`.
- Отсутствуют контрактные тесты между backend response и frontend DTO для staged-полей.
- Риск повторного расхождения frontend/backend-типов в будущем без такой проверки.

## Scope задачи

- Исправить тип `senderUserId` на `string | null` в `chat-api.ts`.
- Добавить контрактные тесты для staged-полей.
- Настроить механизм предотвращения расхождения типов в будущем.
