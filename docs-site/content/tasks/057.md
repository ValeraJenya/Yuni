## Статус

`review` · P0

## Finding

Privacy и notification settings представлены в UI, но для них нет целостного backend API/persistence contract. Пользователь может считать, что настройка применена, хотя server state не меняется.

## Scope

Определить authoritative settings model, GET/PATCH endpoints, defaults, authorization и фактическое применение к Discovery/notifications.

## Acceptance

- UI загружает и сохраняет server state;
- privacy gates применяются на backend, а не только визуально;
- notification producers учитывают preferences;
- defaults/migrations и end-to-end scenarios документированы.

## Реализация

Добавлен backend-only модуль `SettingsModule` с guarded endpoints:

- `GET /settings/privacy`
- `PATCH /settings/privacy`
- `GET /settings/notifications`
- `PATCH /settings/notifications`

Privacy API читает и частично обновляет `profileVisibilityMode`, `showDistance`, `showOnlineStatus`, `showDisplayNameInPrivateMode`, `showBioInPrivateMode`, `showLocationInPrivateMode`, `discoverable`, `allowMessagesFromMatchesOnly`. Notification API читает и частично обновляет `likesEnabled`, `matchesEnabled`, `messagesEnabled`, `productUpdatesEnabled`.

## Non-goals

Не добавлялась новая enforcement-логика для geo-distance, online presence или like-notification producer. Существующие Discovery/privacy/notification gates не переписывались.

`anonymousAvatarKey` не выведен в API в этой реализации: поле выглядит как internal storage key и требует отдельного owner/security решения перед экспонированием.
