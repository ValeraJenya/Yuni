## Статус

`idea` · P2

## Finding

`cursor` объявлен как `@IsOptional() @IsString()` без `@IsUUID()` в двух
независимых DTO:

- общем `apps/backend/src/common/pagination/cursor-pagination.dto.ts`;
- собственном `apps/backend/src/modules/discovery/dto/discovery-cards-query.dto.ts`.

DTO именно два, и они не наследуют друг друга, поэтому починка одного общего
разом обе не закроет.

Значение уходит в Prisma по uuid-колонке в пяти местах:
`moderation.service.ts:180`, `chat.service.ts:349`, `chat.service.ts:398`,
`notifications.service.ts:183` (все четыре как `cursor: { id }`) и
`discovery.service.ts:104` (как `cursor: { userId }`).

Механизм тот же, что в Task 060, но через query, а не path: невалидный UUID
доходит до Prisma, та бросает `P2023`, `AllExceptionsFilter` не распознаёт
ошибку как `HttpException` и отдаёт 500 вместо 400.

## Scope

Добавить `@IsUUID()` к `cursor` в обоих DTO. Покрыть e2e хотя бы один
endpoint на каждый из двух DTO — иначе второй останется незамеченным ровно по
той причине, по которой он и появился.

## Acceptance

- невалидный `cursor` в query даёт 400, а не 500, на всех пяти путях;
- корректный несуществующий cursor не ломает нормальный путь;
- оба DTO покрыты, а не только общий.

## Источник

Найдено при выполнении Task 060 (PR #79). Руками не воспроизводилось — только
чтение кода, поэтому 500-й на query подтверждён рассуждением по коду, а не
прогоном.

## Связь

Смежно с более крупной задачей о разборе Prisma-ошибок в
`AllExceptionsFilter`: точечная валидация закрывает класс ошибки в конкретных
точках, но не сам факт, что `P2023` превращается в 500.
