## Статус

`done` · P1

## Связь

Связана с Task 023, но имеет отдельный deletion-consistency scope.

## Finding

При удалении фото DB row удаляется раньше файла, ошибка storage delete подавляется, а static serving отдаёт файл с диска без сверки с БД. Удалённое пользователем фото может остаться публично доступным по старому URL.

## Scope

Выбрать recoverable delete lifecycle: quarantine/tombstone/retry/garbage collection и недоступность URL сразу после пользовательского delete.

## Acceptance

- после успешного API delete старый URL больше не раскрывает фото;
- storage failure наблюдаем и повторяется безопасно;
- DB/storage consistency покрыта integration tests;
- cleanup не удаляет чужие файлы.
