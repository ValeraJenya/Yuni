## Статус

`review` · P3 — ветка `chore/task-084-repo-hygiene`.

## Finding

В репозитории не было `.gitattributes` — переводы строк и бинарные типы
никак не размечены, каждый инструмент и каждая машина решают сами. Два
разработчика на Windows, `git add` печатал `LF will be replaced by CRLF`
на каждом коммите.

`.gitignore` не содержал записей про `.claude/` и про `*.tsbuildinfo` —
`.claude/launch.json` и `apps/frontend/tsconfig.tsbuildinfo` подтягивались
в `git status` как untracked-шум при каждом заходе в репозиторий.

## Acceptance

- `.gitattributes` в корне: нормализация текста, явные бинарные типы,
  которые реально есть в индексе;
- `.gitignore` дополнен без удаления существующих записей;
- `.claude/settings.json` остаётся отслеживаемым;
- нормализация не переписывает ни одного файла в индексе — доказано
  `git add --renormalize .` с пустым `git status --short` после;
- каждое новое правило `.gitignore` подтверждено `git check-ignore -v`.

## Источник

Инвентаризация 2026-08-20 (Task 084 в `ROADMAP.md`, `idea`); постановка и
уточнения по `eol` / структуре `.gitignore` — владелец, 2026-08-25.

## Решение

### Расхождение с постановкой задачи

Постановка задачи заявляла на `origin/main@39c4082`: 442 файла `i/lf`, 23
`i/-text`, 3 «пустых», итого 468. Замер `git ls-files --eol` на том же
коммите (git 2.52.0.windows.1) дал другие числа: **445 `i/lf`, 31
`i/-text`, 3 `i/`-пустых (479 всего)**. CRLF-в-индексе — ноль, это
совпало. Три «пустых» файла — не пустые файлы, а gitlinks трёх Hugo-тем
(`docs-site/themes/book`, `lotusdocs`, `relearn`): у submodule-записей
`eol` всегда пустой, `git ls-files` не отличает их от пустых файлов в
этом выводе.

Расхождение зафиксировано и подтверждено владельцем как повод продолжать
по фактическим цифрам, а не по заявленным — инструкция задачи требовала
остановиться именно на этот случай.

### `.gitattributes`

```gitattributes
* text=auto eol=lf

*.png binary
*.jpg binary
*.webp binary

pnpm-lock.yaml linguist-generated=true
```

**Бинарные типы** — только то, что реально даёт `i/-text` в
`git ls-files --eol`: `.png`, `.jpg`, `.webp`. Ничего не добавлено по
догадке.

**`eol=lf`, а не оставить на `core.autocrlf`.** Аргумент: CRLF в индексе
уже сейчас ноль, то есть `eol=lf` ничего не переписывает сегодня — он
только убирает повод для будущего предупреждения `LF will be replaced by
CRLF`, которое иначе продолжало бы печататься при каждом `git add` на
обеих Windows-машинах. Минус, который стоит держать в уме: `eol=lf`
навязывает LF в рабочей копии **обоим** разработчикам одновременно, а не
только тому, кто его завёл — если у кого-то локально есть Windows-специфичный
инструмент, чувствительный именно к CRLF на диске, это сломает его молча.
Явных таких инструментов в репозитории нет: `.bat`/`.cmd`/`.ps1`/`.sh` в
индексе не найдено. Подтверждено владельцем.

**`pnpm-lock.yaml linguist-generated=true`, без `-diff`.** Мотив
добавления — PR #91 дал +499 строк лока, такие диффы приходится
пролистывать в каждом PR с новой зависимостью;
`linguist-generated=true` решает это на уровне GitHub: файл сворачивается
в PR-вьюере по умолчанию, разворачивается по клику. `-diff` рассмотрен и
отклонён: он не только сворачивает файл в GitHub UI, но и глушит
`git diff`/`git log -p` локально — а это ровно тот инструмент, которым
`/code-review` и `/security-review`, да и человек глазами, ловят
неожиданный пакет, затесавшийся в лок при апдейте зависимости. Цена
`-diff` (потеря сигнала на локальном review) выше выигрыша
(`linguist-generated` уже решает исходную жалобу — пролистывание PR на
GitHub).

### `.gitignore`

```gitignore
# Build artifacts
*.tsbuildinfo

# Claude Code: machine-local files. .claude/settings.json stays tracked,
# and .claude/skills/ (once it exists) should ride through git too — listed
# individually rather than ignoring .claude/ wholesale.
.claude/settings.local.json
.claude/launch.json
```

Три конкретные записи, не `.claude/` целиком — `.claude/settings.json`
должен остаться отслеживаемым, а будущий `.claude/skills/` должен ездить
через git по умолчанию. Рассмотрена альтернатива «игнорировать всё в
`.claude/` с явными исключениями» (`.claude/*` + `!.claude/settings.json`
+ `!.claude/skills/`) — не выбрана: она защищает от будущего шума ценой
риска молча спрятать файл, который должен был уехать через git, но для
которого забыли дописать `!`-исключение. Три явные записи закрывают
ровно то, что не игнорируется сегодня, без этого риска.

Существующие записи `.gitignore` (`docs-site/cd`, `docs-site/git`,
`docs-site/xcopy` — следы чужих опечаток в командах) не тронуты.

### Другие пробелы — проверено, не найдено

- `apps/backend/dist/` в рабочей директории уже покрыт существующим
  правилом `dist/` (`git check-ignore -v apps/backend/dist` подтверждает).
- Ничего случайно не закоммичено: `git ls-files` проверен на
  `node_modules`, `.env`, `/dist/`, `.next/`, `.DS_Store`, `*.log` —
  единственное совпадение `.env.example`, который и должен быть
  отслежен (`!.env.example` в `.gitignore`).
- `.vscode/`, `.idea/`, `*.log`, `.eslintcache`, `Thumbs.db`, docker
  override-файлы в рабочей директории не найдены.
- Untracked-мусор в корне репозитория (`*.patch`, `prompt-*.md`,
  `spec-*.md`, `codex-*.diff`) в `.gitignore` не добавлен: это не
  build-артефакты, а личные рабочие файлы владельца — не территория этой
  задачи.

## Evidence

Все команды — на ветке `chore/task-084-repo-hygiene`, локально, git
2.52.0.windows.1:

```
$ git ls-files --eol | awk '{print $1}' | sort | uniq -c
    445 i/lf
     31 i/-text
      3 i/
```

До и после `.gitattributes`/`.gitignore` — распределение не изменилось
(проверено дважды: сразу после `.gitattributes`, и повторно после
`.gitignore`).

```
$ git add --renormalize . && git status --short
```

Пусто по всем tracked-файлам оба раза — только сам `.gitattributes` и
(до второго прогона) правка `.gitignore` появляются как ожидаемые
изменения; ни один существующий файл не помечен как изменённый.

```
$ git check-ignore -v apps/frontend/tsconfig.tsbuildinfo
.gitignore:33:*.tsbuildinfo	apps/frontend/tsconfig.tsbuildinfo

$ git check-ignore -v .claude/settings.local.json
.gitignore:38:.claude/settings.local.json	.claude/settings.local.json

$ git check-ignore -v .claude/launch.json
.gitignore:39:.claude/launch.json	.claude/launch.json

$ git ls-files .claude
.claude/settings.json
```

Все три новых правила срабатывают на нужный путь; `.claude/settings.json`
остался единственным отслеживаемым файлом в `.claude/`.

## Осталось за рамками

- Untracked-мусор в корне репозитория (патчи, prompt-файлы) — не тронут,
  не территория задачи.
- Существующие странные записи `.gitignore` (`docs-site/cd`,
  `docs-site/git`, `docs-site/xcopy`) — не тронуты по прямому указанию.
- Рабочая копия на диске у файлов с `i/lf` продолжает показывать `w/crlf`
  до следующего чистого checkout — `eol=lf` меняет поведение будущих
  checkout'ов, не переписывает уже лежащие на диске файлы задним числом.
